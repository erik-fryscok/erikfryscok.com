# Agent Instructions

## GitHub context

- **Repository:** erikfryscok.com
- **Owner:** erik-fryscok

## Before making changes

1. Read [docs/README.md](docs/README.md), then the product brief and any documentation linked by the active GitHub issue.
2. Work from a GitHub issue whenever the change is more than a trivial correction.
3. Respect the content boundaries in [docs/product/brief.md](docs/product/brief.md): do not expose employer or client confidential information, proprietary material, credentials, or non-public designs.

## While making changes

- Keep product intent, decisions, experiment outcomes, and released changes in Git; keep live delivery status and scope in GitHub.
- Update documentation when behavior, architecture, product intent, or an established decision changes.
- Add a decision-log entry when a meaningful choice would otherwise be revisited.
- Update `CHANGELOG.md` for user-visible changes intended for the next formal release.
- Do not create duplicate Markdown roadmaps, status tables, or task checklists.

## Before handing work off

- Link the pull request or change to its GitHub issue.
- Validate relevant documentation links and Markdown.
- State whether documentation, decisions, and the changelog were updated or why they were not applicable.
